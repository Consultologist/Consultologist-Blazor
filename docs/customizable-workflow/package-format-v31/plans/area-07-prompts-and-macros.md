# Area 07: Prompts and Macros (specVersion 31) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give specVersion 31 its template language: check every body of a package against the Consultologist Scriban dialect at publish (statements, built-ins, reads, placements, renderers, snippets, parts, macros), tell the resolver what each body reads, and compose at run time what a model is sent and what its reply becomes (snippets, parts, renderers, run spots with two hashes, macro markers checked and replaced literally), with a folder macro's marker tested from the rendered prompt through the reply to the result.

**Architecture:** Everything that reads or renders a template is a pure library, `src/Consultologist.PackageFormat/V31/Templates/`. At publish, `TemplateSyntax` reads one body (Scriban's parser plus a tag scanner for whitespace marks), `SourceTemplates.Check` holds every body of a package to part 05 in the scope the resolver gives and returns a `PackageTemplates`, which is the real `ITemplateReads` and also says each entry's `placements` and `names` for `resolve.json`. At run time the runner decides every placement's header `if` (JSON Logic, recorded) and hands the results to the host; `AgentTurn.Prepare` composes the sent text with `BodyComposer`, and `AgentTurn.Finish` checks the reply's markers and substitutes with `MacroReply`. The Api's two activities become thin callers of `AgentTurn` and `BodyComposer`, so tests run the same code with no Azure.

**Tech Stack:** C# / .NET 10, Scriban 7.2.5 (pinned), Markdig 0.41.3, `System.Text.Json` (`JsonNode`), areas 02 to 06's services (`ScopeTree`, `FormatReads`, `FormatTypes`, `SentFormat`, `CanonicalJson`, `RunPlan`, `PlanRunner`), xUnit in `tests/Consultologist.Api.Tests.csproj`.

**Spec:** `docs/customizable-workflow/package-format-v31/` — [`05-templates-and-macros.md`](../05-templates-and-macros.md) in full (its *Refusals* list is the sentence list; `refusal-sentences.md` rows S05-001 to S05-064), with [`02-types-and-inputs.md`](../02-types-and-inputs.md) §§ 2.1, 3.5, 5, 5.3, [`03-expressions.md`](../03-expressions.md) §§ 4.2, 4.4 to 4.6, [`04-loops-and-functions.md`](../04-loops-and-functions.md) §§ 2.5, 2.6, 7.3, 7.4, 7.7, 7.10, [`06-checks-deliverables-profile.md`](../06-checks-deliverables-profile.md) §§ 6.2, 6.3, 6.4 (escaping only), 10.1, 10.2, [`07-compiled-documents.md`](../07-compiled-documents.md) §§ 2.5, 3.1, 4, [`08-record.md`](../08-record.md) §§ 2.3, 4, 4.2, 4.3, 5, 8, and [`09-engine-and-pages.md`](../09-engine-and-pages.md) § 3.4. ## Review Focus

1. **A reply that plays with markers.** A marker inside a code fence; the same marker twice; a block marker indented by a tab with trailing spaces; a near-miss (`{{macro.x.content}}`, `{{ macro.X.content }}`); a marker for a macro of another node; a reply that is only a marker; a reply holding `{{ for x in y }}` or `{{ include 'a' }}`; a macro body that itself contains another macro's marker text or `{{run:1}}`. Expected: each is judged by § 8.6 exactly, the substituted text is never scanned again, and nothing the model wrote is ever parsed as a template. (Task 10 `MacroReplyTests.AnyReply_IsJudgedLiterally`.)
2. **Values that look like syntax.** An input whose text is `{{ node.x.content }}`, `{{run:1}}` or `{%{`; a snippet body holding a raw block; a profile signature holding `{{ macro.a.content }}`. Expected: values are spliced as text, a run spot is filled at its recorded position and never found by search, and both hashes are stable. (Task 9 `ARunSpotMarkerInAValue_IsLeftAsItIs`; Task 8 `AValueHoldingBraces_IsNotRendered`.)
3. **Templates built to exhaust the render.** Three nested `for`s over 200-item lists; a snippet placed in a `for` over a 1,000-item list; a renderer piped per item; output just under and just over 1 MiB in multi-byte characters; 16 levels of nesting; a snippet chain 16 deep. Expected: publish refuses what it can (S05-013), and a render stops at its limit with the limit's sentence, never a hang, never Scriban's message. (Task 8 `EachLimit_StopsTheRenderWithItsSentence`.)
4. **A unit placed where its reads are not there.** A snippet reading `item` placed outside a loop; a snippet reading `profile.*` placed in a prompt and in a macro body; a macro whose `if` reads a node that is local to one of two placers; the same snippet placed at the package level and inside a function. Expected: each placement is judged where it is placed (S05-022, S05-021, S04-063), and at run time each placement's `if` reads its own place's keys. (Task 5 `ASnippet_IsCheckedInEveryPlaceItIsPlaced`; Task 11 `APlacementsIf_ReadsItsOwnPlace`.)
5. **A header a hand wrote wrongly.** A part with no `text`, `text` a string, an unknown part member; a macro `instruction` of zero lines, or with its marker in a comment or a raw block; a snippet folder item whose header is an array; a renderer whose `input` is a format that does not exist. Expected: a refusal with a sentence, never an exception. (Task 5 `AnyPartsMember_IsRefusedOrRead_NeverThrows`; Task 6 `AMarkerInACommentOrARawBlock_IsNoMarker`.)
